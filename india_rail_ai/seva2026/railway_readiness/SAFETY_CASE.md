# Safety case (draft structure with evidence, for Indian Railways review)

Structure follows the EN 50129 safety-case layout, applied to an **advisory** function. Sections marked
**[IR]** can only be completed by Indian Railways or an independent safety assessor.

## 1. System definition
* Function: rank conflict-free alternatives after a disruption for a section controller; show the approved plan
  to drivers as advice. Inputs: timetable (open/official), infrastructure attributes (inferred/official), positions
  (projection or authorised feed), section events. Outputs: advisory rankings, threats, cab advisories, audit.
* Boundary: no outputs to signalling, interlocking, points, Kavach/ATP, brakes or block instruments. Movement
  authority stays with signals and staff under the General & Subsidiary Rules.
* Architecture: `india_rail/railguard/` (twin, planner, evidence gate, threats, cab, audit, feed gateway), FastAPI
  service with role-based access, browser consoles. Diagram and data flow: report sections 2 and 8.

## 2. Safety requirements (developer proposal)
| ID | Requirement | Implemented by | Verified by |
|---|---|---|---|
| SR1 | Never present a plan with a planned occupation conflict as feasible | `national.candidates/_resolve/_priority_path`, `planner.recommend` | RANKING, SAFE_SEPARATION invariants |
| SR2 | Never allow approval on stale/missing mandatory evidence or with an open critical threat | `evidence.py`, `engine/national.recommend` | EVIDENCE_GATE, APPROVAL_GATE |
| SR3 | Approval only of the latest ranking for the current state, by a named controller | version check in `approve` | APPROVAL_GATE, `test_superseded_*` |
| SR4 | Never route over a closed/obstructed/axle-limited section | feasibility filter | RANKING |
| SR5 | Cab never shows a proceed status or speed band without fresh evidence and an approved plan | `cab.py`, `national.cab` | CAB_ADVISORY |
| SR6 | Reject malformed, replayed, future or impossible observations | `engine.ingest_position`, `livefeed.py` | INPUT_REJECTION, `test_livefeed.py` |
| SR7 | Every decision reconstructable and tamper-evident | `audit.py`, replay | REPLAY, audit tests |
| SR8 | Fail closed when security is misconfigured | `security.py` | `test_production_*` |

Integrity level: an advisory function outside the safety chain; the developer proposes **Basic Integrity**
(EN 50716) with SIL-style practices applied voluntarily. **[IR]** confirm the allocation from the hazard analysis.

## 3. Quality management evidence
Version control with reviewed pull requests; CI on every push (lint with pinned ruff 0.8.6, 215 automated tests on
Python 3.11); pinned dependencies with SCA (pip-audit 0); SAST (Bandit 0); five documented audit passes
(`../AUDIT_LOG.md`); evidence files generated by scripts, not typed by hand.

## 4. Safety management evidence
Hazard log (`HAZARD_LOG.md`); randomised verification (`../../india_rail/railguard/simulate.py`, 8 invariants, 5M+
operations in the main run, which found one last defect, since fixed; 1,201,001 operations with 0 violations on
the code before real data; on the final code with real data and the learned forecast, 3,187,925 operations in
236,000 episodes with 0 violations; every finding reproducible from its seed);
deterministic replay (1,585 consecutive replays, 0 mismatches).

**Verification on real-life data** (`REAL_DATA_VALIDATION.md`, `../evidence/real_data/real_validation.json`): the
twin runs on the September 2024 timetable with running days observed for every train and track data mapped on
90% of sections; 56,395 real train runs (1.26M actual arrivals) were used to check data credibility against the
Ministry's published punctuality, to score delay forecasts forward in time on unseen days, to test whether conflict
warnings precede real time loss, and to replay a real morning through the signed feed gateway. Ten defects found
this way are fixed (`../AUDIT_LOG.md`, pass 6).

## 5. Technical safety report (summary)
Fourteen system defects (and one harness defect) were found by the randomised verification and fixed before this
report (AUDIT_LOG.md, pass 1); ten more were found by running against real-life data, including one the randomised
simulation caught in the new forecast code (AUDIT_LOG.md, pass 6).
No known open defect violates SR1-SR8. Known limitations: no block-section, loop or signal data in public sources
(conflict warnings are measured to be informative but far from certain, H14); one month of observed running
(September, no fog season); OpenStreetMap is volunteer-mapped; human-factors behaviour of the cab display not yet
trialled.

## 6. Related safety cases and interfaces
None in the signalling safety chain. Data interfaces: authorised feeds via the signed gateway
(`LIVE_DATA_INTERFACE.md`), whose correctness depends on the source system's own assurance. **[IR/CRIS]**

## 7. Conclusion and conditions of use (proposed)
Fit for a **shadow-mode trial** (advice observed, not acted on) subject to: IR hazard workshop; CERT-In/STQC audit;
hosting on IR infrastructure; the trial plan in `SHADOW_TRIAL_PLAN.md`. Use of advice in live operation only
after the trial evidence, IR acceptance and independent assessment. **[IR / ISA / RDSO]**
